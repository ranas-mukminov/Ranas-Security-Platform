# ScopeProof Lab

**Authorized Security Research · Reproducible Validation · Scope-Aware Evidence**

*run-as-daemon.dev · Open-source educational research tooling*

> **Status: v0.1 alpha. Offline and synthetic only.** The two demonstrations are deliberately vulnerable fixtures, not vulnerabilities in any real product. This project does **not** scan or contact real hosts, and does not grant permission to test an organization.

ScopeProof Lab is a small, reproducible lab for reviewing the steps of a permissioned security assessment: checking a declared scope, reproducing a problem in a synthetic environment, validating a patch, and generating a hash-linked report.

## What works today

| Component | What v0.1 actually implements |
| --- | --- |
| Scope Guard | JSON policy schema validated fail-closed: loopback-only host/source, allowed method/port, timezone-aware dates, action ceiling, emergency stop |
| AUTHZ-LAB-001 | Local in-memory object access with an intentional missing ownership check; the patched version denies cross-user access |
| RBAC-LAB-001 | Analysis of two synthetic Kubernetes Role/ClusterRole **JSON** manifests: wildcard cluster permission vs least-privilege role |
| Evidence Chain | Events stored in JSONL, chained via SHA-256, independently verified by CLI |
| Report | Markdown showing results before and after remediation, plus final evidence-chain head |
| CI | Unit tests and synthetic demo on Python 3.11/3.12 (when the workflow is installed at repository root) |

## Quick start

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
scopeproof demo --out artifacts/my-first-run
scopeproof verify --events artifacts/my-first-run/events.jsonl
cat artifacts/my-first-run/report.md
```

Requires Python 3.11+. The runtime has no third-party Python dependencies. Installation may use standard Python build tooling. The demo uses only the standard library; it does not need Docker, Kubernetes, cloud credentials, or network access.

### Example: reject a target outside the local laboratory

```bash
scopeproof check-scope \
  --policy examples/policy.template.json \
  --url https://example.org:443/ \
  --source-ip 127.0.0.1 \
  --method synthetic_authz
# {"allowed": false, "reason": "target host, URL or port not in local scope"}
# exit code 3
```

*No connection is attempted.* A declared scope is neither verified consent nor a legally binding permission document. A real assessment requires signed rules of engagement, explicit asset ownership/permission and clear contractual boundaries separate from this tool.

## Sample evidence

The report is generated by `scopeproof demo`; it records the deliberate insecure behavior and shows the same scenario is blocked by the patch. Event digests detect casual modification, **not** a sophisticated operator rewriting the whole chain: keep the final digest in an independent store.
